⚙️ Smart Priority System

How it works: When you mark tables as ✓ Correct or ✗ Incorrect for specific queries, the system learns query-intent patterns and automatically applies them to similar future queries.

Example - Location Queries

Query: "give me bot locations"
Wrong table selected: dashboard_bot_master (has LOCK_BY, UNLOCK_BY - admin metadata)
Right table: bot_master (has GRIDX, GRIDY, GRIDZ - actual position coordinates)

Solution:
1. Test query "give me bot locations"
2. Mark dashboard_bot_master as ✗ Incorrect
3. Mark bot_master as ✓ Correct
4. System saves this validation
5. Next time any query mentions "bot locations" → bot_master gets 10× boost, dashboard_bot_master gets 0.01× penalty

Similarly for stations:
"station locations" → hw_station_master ✓ (has LOCATION_ID, station data)
"station locations" → hardware_registered ✗ (generic hardware, not station-specific)

📋 Validation-Based Learning (Query → Table Mapping)

Use the Test Query panel above to validate correct/incorrect tables. The system automatically learns from your validations and applies:

  • 10× boost for validated correct tables
  • 0.01× penalty for validated incorrect tables
  • Exact query matching (case-insensitive)
  • Stored persistently across sessions

🎛️ Category Priority Multipliers (Fallback)

These are default multipliers applied when no validation exists for a query:

Priority Execution Order

  1. Validation Rules First: If exact query match found → apply 10× boost/0.01× penalty
  2. Category Multipliers Second: Apply category-based multipliers (bot_master: 3.0×, etc.)
  3. Entity Boost Third: If query mentions "bot" → boost bot_* tables by 1.5×
  4. TF-IDF Similarity Fourth: Match query keywords with table descriptions
  5. Final Ranking: Top 8 tables with highest combined scores
