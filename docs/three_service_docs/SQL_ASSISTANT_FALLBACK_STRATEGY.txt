Problem Solved: JOIN path failures with 180+ tables
================================================================================

PROBLEM STATEMENT
-----------------
User Query: "give me all the sku name and sku id who is not ordered in last 1 year"

Original Behavior:
  1. LLM extracts: base_table = "stock_audit_wave_order_master"
  2. System tries JOIN to "sku_master_dsb_upload_validation"
  3. No path exists in schema graph
  4. ❌ FAILS with error: "No join path from X to Y"
  5. User gets error message

Issue: With 180 tables, there are often multiple valid ways to answer a query.
       The system was too rigid - it would fail instead of trying alternatives.

================================================================================
SOLUTION: INTELLIGENT FALLBACK LOOP
================================================================================

NEW BEHAVIOR
------------
1. LLM extracts semantic frame (base_table + dimensions)
2. System attempts to resolve JOINs with initial base table
3. ✅ If successful → Build SQL and execute
4. ❌ If failed → Try next best alternative base table
5. Repeat up to 5 attempts
6. Use first successful combination

FALLBACK STRATEGY FLOW
-----------------------

Attempt 1: Primary Base Table (LLM + Resolver)
  - Use LLM's suggested base_table
  - Apply base table resolver correction
  - Try to resolve all JOIN paths
  - If success → Done
  - If failure → Continue to Attempt 2

Attempt 2-5: Alternative Base Tables
  - Score all remaining tables based on:
    * Column ownership (filters, metrics, dimensions)
    * Semantic match with question
    * Schema graph connectivity
    * Exclude already-tried tables
  - Pick highest scoring alternative
  - Try to resolve all JOIN paths
  - If success → Done
  - If failure → Continue to next attempt

After 5 Attempts:
  - If no success → Return detailed error:
    * Which tables were tried
    * Which dimensions were needed
    * Suggestions for user

1. ENHANCED BASE TABLE RESOLVER
   File: query/base_table_resolver.py
   
   New Method: get_alternative_base_tables()
   ```python
   alternatives = resolver.get_alternative_base_tables(
       frame=frame,
       user_question=question,
       exclude_tables=['already_tried_table']
   )
   # Returns: [('table_name', score), ...] sorted descending
   ```
   
   Improved Scoring:
   - Filter ownership: +3 points
   - Metric ownership: +2 points
   - Dimension ownership: +2 points (NEW)
   - Semantic match: +3 points
   - Connectivity: +(count * 0.1) points
   
   Returns ranked list of all viable tables

2. CORE FALLBACK LOOP
   File: core.py
   
   Logic:
   ```python
   max_attempts = 5
   tried_tables = []
   
   for attempt in range(1, max_attempts + 1):
       if attempt == 1:
           base_table = resolve_primary(frame)
       else:
           alternatives = get_alternatives(exclude=tried_tables)
           base_table = alternatives[0]
       
       tried_tables.append(base_table)
       frame.base_table = base_table
       
       # Validate frame
       frame = validate_and_repair(frame)
       
       # Try JOIN path resolution
       join_paths = {}
       all_found = True
       
       for dimension in frame.dimensions:
           path = schema_graph.get_join_path(base_table, dimension)
           if not path:
               all_found = False
               break
           join_paths[dimension] = path
       
       if all_found:
           # SUCCESS - build SQL
           sql = build_sql(frame, join_paths)
           break
   ```

3. DIMENSION TABLE RESOLVER (NEW COMPONENT)
   File: query/dimension_table_resolver.py
   
   Purpose: Find alternative dimension tables when direct ones fail
   
   Methods:
   - find_alternative_dimensions(base_table, target_columns)
     Returns alternative tables that have the same columns
   
   - get_reachable_tables(base_table, max_hops=3)
     Returns all tables within N JOINs of base_table
   
   Usage:
   ```python
   alternatives = dimension_resolver.find_alternative_dimensions(
       base_table='order_master',
       target_columns=['SKU_ID', 'SKU_NAME']
   )
   # Returns: {
   #   'SKU_ID': {'table': 'sku_master', 'path': [...], 'confidence': 0.95},
   #   'SKU_NAME': {'table': 'sku_master', 'path': [...], 'confidence': 0.95}
   # }
   ```

EXAMPLE: HOW IT WORKS
================================================================================

User Query: "give me all the sku name and sku id who is not ordered in last 1 year"

Attempt 1:
  Base: stock_audit_wave_order_master
  Dimensions: [SKU_ID, SKU_NAME] from sku_master_dsb_upload_validation
  JOIN Path: stock_audit_wave_order_master → sku_master_dsb_upload_validation
  Result: ❌ No path found
  
Attempt 2:
  Base: order_master (alternative, score: 15.2)
  Dimensions: [SKU_ID, SKU_NAME] from sku_master_dsb_upload_validation
  JOIN Path: order_master → sku_master_dsb_upload_validation
  Result: ❌ No path found
  
Attempt 3:
  Base: order_line (alternative, score: 12.8)
  Dimensions: [SKU_ID, SKU_NAME] from sku_master_dsb_upload_validation
  JOIN Path: order_line → sku_master_dsb_upload_validation
  Result: ❌ No path found
  
Attempt 4:
  Base: sku_master (alternative, score: 10.5)
  Dimensions: [ORDER_DATE] from order_master
  JOIN Path: sku_master → order_master → order_line
  Result: ✅ Paths found!
  
SQL Generated:
  SELECT sku_master.SKU_ID, sku_master.SKU_NAME
  FROM sku_master
  LEFT JOIN order_line ON sku_master.SKU_ID = order_line.SKU_ID
  LEFT JOIN order_master ON order_line.ORDER_ID = order_master.ORDER_ID
    AND order_master.ORDER_DATE >= DATE_SUB(NOW(), INTERVAL 1 YEAR)
  WHERE order_line.ORDER_ID IS NULL
  LIMIT 100
